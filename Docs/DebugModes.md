# Cosmos 개발용 디버그

PIE 또는 Development 빌드에서 사용한다. Shipping에서는 아래 명령과 단축키가 아무 동작도 하지 않는다. 플레이 화면을 클릭해 게임 입력을 받은 상태에서 단축키를 누른다. 에디터의 Output Log보다 게임 콘솔(`~`)에 명령을 입력하는 것을 권장한다.

| 단축키 | 콘솔 명령 | 동작 |
| --- | --- | --- |
| F1 | `CosDebugHelp` | 현재 날짜·체력·무적·배속 및 단축키 도움말 표시/숨김 |
| F2 | `CosDebugBoss` | 전장을 새로 열어 7일차 보스전 시작 |
| Ctrl + 1~7 | `CosDebugDay 1` ~ `CosDebugDay 7` | 선택한 날짜 시작 |
| F3 | `CosDebugGod` | 실제 피해를 차단하는 무적 켜기/끄기 |
| F4 | `CosDebugRefill` | 체력·샷건 탄약·포션 최대치 충전 |
| F5 | `CosDebugKillEnemies` | 현재 살아 있는 적에게 치명적 피해. 정상 처치 보상과 진행 이벤트 발생 |
| F6 | `CosDebugRestart` | 현재 날짜를 처음부터 다시 시작 |
| F7 | `CosDebugSpeed 1` | 단축키는 1배 → 2배 → 0.25배 순환. 콘솔은 0.1~5배 지정 가능 |
| F9 | `CosDebugBossDamage 10` | 보스 최대 체력의 10% 피해. 콘솔에서 0 초과~100% 지정 |
| 없음 | `CosDebugPlayerDamage 10` | 플레이어에게 10 피해. 무적·피격 HUD·사망 흐름 확인용 |
| 없음 | `CosDebugSoul 1000` | 소울 1,000 추가. 1~1,000,000 범위 |

## 날짜 이동과 상태

날짜 이동은 `L_BlockoutAstra`를 새로 연다. 이전 적·투사체·튜토리얼 타이머·결과창·쓰러지는 연출을 새 전장으로 가져오지 않는다. 무적·배속·디버그 도움말도 초기화된다. 게임 인스턴스가 가진 소울·장비·인챈트는 유지된다. 새 PIE 세션은 일반 1일차로 시작한다.

2~7일차 바로 시작에서는 튜토리얼 사슴을 생성된 월드에서 정리한다. 1일차 재시작은 살아 있는 사슴과 기존 인챈트 획득 조건을 복원한다. F5는 현재 생성된 적만 처치하므로 생존 스테이지의 다음 스폰은 계속된다. 튜토리얼 사슴은 F5 대상이 아니다.

사망 후에는 충전으로 부활하지 않고 F6 또는 날짜 이동 명령으로 재시작한다. UI 전용 입력 상태에서는 게임 콘솔로 재시작할 수 있다.

## 보스 HUD

`UCosBossHealthWidget`이 기존 `/Game/Cosmos/WBP/WBP_HPBar`를 재사용한다. 이름과 별도 사각 배경은 없으며 보스의 `UHealthComponent`에 연결된 붉은 체력·수치만 표시한다. 위젯 클래스와 상단 배치 크기는 `CosBossHealthWidget`에서 조정한다. 원본 플레이어 체력바 에셋은 변경하지 않는다.

## 검증

PIE 자동 검증 스크립트와 결과, 실제 화면 캡처는 `Saved/DebugModes`에 저장된다. 빌드/패키징 결과와 PIE 검증은 별개이며 Shipping 패키지 실행 검증은 별도로 진행한다.

2026-09-28: `CosmosEditor Win64 Development` 전체 빌드 통과. 콘솔 명령을 통한 PIE 자동 검증에서 보스전 진입, 실제 피해로 무적 ON/OFF 확인, 충전, 소울 추가, 배속, 보스 10% 피해와 체력바, 도움말 표시, 정상 보스 사망 결과창, Day3 이동/재시작, Day1 사슴 복원까지 통과했다. 물리 키 입력과 Shipping 패키지 실행은 자동 검증 범위에 포함하지 않았다.
